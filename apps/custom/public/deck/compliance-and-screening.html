The problem

You screened once, at onboarding. The world moved.

What a trade-compliance team will tell you:

"We screen against OFAC at onboarding. We do not re-screen when OFAC updates the SDN list — which is basically weekly."

Stale clearances

"A name match in our old tool is treated as a legal-identity match. Analysts waste days clearing false positives with no way to record why."

False positives

"When we clear a party, that's a status field someone can overwrite. There's no immutable record of the hit that was there before."

No audit trail

How Qubere addresses it

Deterministic verdicts. Immutable results. Continuous re-screening.

  • Every verdict comes from a rule table and a scorer you can inspect — not a model that sounds confident.
  • Results are frozen. Reviewer judgment (False Positive / Blocked / Approved) is a separate 1:1 record — a clean run never erases an earlier hit.
  • RDPS re-screens cleared parties automatically when their data changes or the watchlist changes — with a drill-down to exactly which parties and why.
  • A tenant can layer its own embargo rules — which can only add a HIT, never manufacture a CLEAR.
  • License determination refuses to fabricate a control-list outcome it can't back with data.

Restricted / denied-party screening

A name match is never legal-identity proof.

Every party is screened against SDN, Consolidated non-SDN, DPL, ISN, SSI, FSE, PLC, NS-MBS — exact, raw-word, and a phonetic shortlist feeding a fuzzy scorer, plus an independent red-flag keyword check. Results are immutable; the disposition is separate.

  • Phonetic algorithm (Double Metaphone / Metaphone2) selectable per account
  • An earlier HIT + its "false positive" note stays on the record forever

RDPS · continuous / reverse screening

The watchlist changed this week. Did your cleared parties get re-checked?

A delta-impact dispatcher reacts to a specific reference-data change within minutes; a full-population dispatcher re-screens the whole account on a schedule. Every outcome records whether the result worsened and a deterministic transition type.

  • NEW_HIT / ESCALATED / RISK_REDUCED / CLEARED / UNCHANGED
  • Preview Impact: what a change would match today — records nothing
  • Hourly sweep catches watchlist entities that expired while still active in every feed

License determination

It will not guess. That is the pitch.

A deterministic engine (never an LLM) runs classification-format validation, tri-state end-use / end-user handling, and license-exception evaluation as pure functions. Because no jurisdiction control-rule datasets are loaded, it never fabricates a LICENSE_REQUIRED / NO_LICENSE_REQUIRED outcome.

  • Returns RULE_DATA_UNAVAILABLE / INCOMPLETE / REVIEW_REQUIRED with full evidence
  • Any sensitive end-use / end-user flag hard-stops to REVIEW_REQUIRED
  • On a positive determination: full utilization ledger, allocations, expiry alerts

Audit, notifications & the partner API

Every screen is provable, and every screen can be a service.

Compliance events queue durable notifications through an outbox/dispatcher (never sent inline, so a mail outage can't lose a hit alert). Every action writes an immutable AuditLog entry. External systems hit the same read/rescreen behavior by API key.

  • Overview / Screening / Review Queue / Audit History workspace
  • /api/v1/screening/* · scoped (read vs screen) · idempotent · source: "API"
  • Every screen is a metered, invoiceable event (see Billing deck)

Objection handling

Every hard question, answered directly.

"Is this an AI making sanctions calls?"No. Every screening verdict is a rule table and a scorer you can inspect. The AI in the platform does analysis inside stages — it never decides a hit.
"Do you do PEP / beneficial ownership?"Not yet — deliberately called out as a known gap, with autonomous approval and deeper fuzzy matching. Denied-party, embargo, and forced-labor coverage is real and continuous.
"License determination sounds like it does nothing."It does the honest thing — it refuses to output a fake control-list answer when the data to back it isn't loaded. For a regulated exporter, "REVIEW_REQUIRED, here's what I checked" is worth more than a guess.
