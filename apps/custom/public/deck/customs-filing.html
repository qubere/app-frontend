Rejections

Duty math

How Qubere addresses it

The data is already here. The entry is a projection of it.

  • The draft assembles from line items, parties, and documents already on the shipment — and fails closed if a destination country, procedure mapping, authority config, or line items are missing.
  • A named 7501 checklist runs before the entry can move, and again — unconditionally — at transmit. Every failure names the field.
  • Duty, MPF, and fees are computed from the actual published HTS schedule, human-approved before it goes live.
  • At transmit, the declaration is frozen and versioned — later shipment edits never rewrite what was filed.
  • Every CBP response maps through a table-driven state machine. Adding a country is seed data.

HTS duty & MPF engine

Duty math you can trace to a published rate.

Not a model, not a heuristic — a specific published HTS release, refreshed nightly from USITC and human-approved before it goes live. If any line is unrated, the duty fields stay blank rather than understating the number.

  • Line-by-line: HTS → rate → extended value → duty
  • Section 301 applied where the rate exists in the data
  • Recomputed at creation, at transmit, and at 7501 build

Canonical multi-country messaging

Adding Germany was a spreadsheet, not a sprint.

Entry type, procedure, authority, message routing, response mapping, allowed post-filing edits, and offered actions all resolve from database tables keyed by (country, procedure), most-specific-match-wins. Germany was onboarded with zero application-code changes.

  • Outbound / inbound messages validated against versioned JSON Schemas
  • A new child action (e.g. AMEND) is one seed row
  • Country/authority code lists (Type/Header/Item/Translation) bulk-load from one CSV, no per-country code
  • Filing Status Catalog gives every response code a canonical label and locale translations

Objection handling

Every hard question, answered directly.

"Are you actually transmitting to CBP / ACE today?"Qubere builds and validates the ABI/ACE message, freezes the declaration, and runs the full response lifecycle — in the demo a simulated CBP response is applied inline. Live ABI transmission activates when a customer's CBP filer credentials are configured (a config switch, not a rebuild); direct ABI certification is on the roadmap.
"What entry types do you support end to end?"All 18 CBP codes are in the vocabulary. The workflow implemented end to end is consumption-style entry (01 / 03 / 11). Warehouse and in-bond exist as types but don't have regime-specific tracking yet.
"Does duty math handle AD/CVD and Section 301?"Section 301 is applied where the rate is in the HTS data. Automated AD/CVD scope and rate ingestion isn't live — flagged for human handling. Unrated lines show blank, never a guess.
