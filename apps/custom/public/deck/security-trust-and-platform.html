Data integrity

How Qubere addresses it

The boundary is enforced in the data layer. The datasets are published.

  • One shared @qubere/db layer — every business query goes through it with accountId scoping.
  • Platform roles for Qubere internal ops are a separate system from customer account roles. Impersonation is banner'd and logged.
  • Every mutating action writes an immutable audit entry — best-effort, so a logging failure never blocks the action it records.
  • Zero-Fabrication Policy: un-wired datasets return HTTP 422 and never fake success. Legally-binding data (tariff rates) has a human publish gate.
  • Scoped partner API — per-scope, idempotent, audit-tagged source: "API".

Tenancy, RBAC & row-level security

Account is the boundary — and it's enforced in the query layer.

Not a view filter, not a middleware afterthought. Auth (identity, MFA, sessions) is Clerk; authorization (roles, permissions) is in Postgres. Within an account, a PLANNER sees only their assigned records — and the AI assistant inherits that because it's the same code path.

  • Built-in roles + custom customer-defined roles
  • API routes enforce capabilities via hasPermission() → 403

SOC2-ready immutable audit log

It can't be turned off, and it can't block your work.

Every administrative and mutating action writes an AuditLog entry: accountId, userId, action, entity, metadata, IP, user-agent, request-id, success/failure. Best-effort write path — a logging failure never blocks or rolls back the action. Shared by every module against a ~104-entry catalogue.

  • Explicitly designed against CBP 19 U.S.C. § 1509 recordkeeping
  • Compliance events also queue durable outbox notifications

Zero-Fabrication data pipeline

We publish which datasets are real — in the admin console.

19 core datasets, each with an explicit status. Un-wired datasets return HTTP 422 and never fake success. A new HTS revision is staged DRAFT and never auto-published — duty rates feed real filings, so a person publishes. One daily dispatcher fans out to all LIVE datasets by their own cadence; staleness fires alerts.

  • OFAC's ~20k-entry SDN list streamed via a durable job to avoid timeouts
  • Every AI run records which model actually ran

Objection handling

Every hard question, answered directly.

"SOC2 report?"The architecture is SOC2-ready — immutable audit, RBAC, tenant isolation, least-privilege data access. Position readiness and the design; get the formal attestation status from sales ops, don't improvise it.
"Can we self-host / air-gap?"The apps are Next.js; the document worker runs as a long-lived process on any host. A fully air-gapped deployment isn't a packaged offering — scope it as an enterprise engagement.
"Data deletion / export on termination?"Bulk shipment/document export exists. A formal end-of-contract data-return/purge runbook is an enterprise contract item, not a self-serve button.
