# CATAIR Gap Closure — Action Plan

Companion to [`CATAIR-FIELD-DB-COVERAGE.md`](CATAIR-FIELD-DB-COVERAGE.md) (the corrected coverage report — see its "Verification Pass Notes" for how the numbers below were established). This document translates that report's **663 MISSING** and **161 PARTIAL** fields (of 925 active business fields, across 12 CATAIR chapters) into concrete Prisma schema work, phased by business criticality.

## 0. Ground rule — do not repeat the citation-hallucination error

The coverage report went through two correction passes because earlier drafts cited Prisma fields that don't exist (`CustomsFiling.payload`, `ShipmentParty.partyId`, `PartyRole.role`, etc. — plausible-sounding names that were never real columns), and even the first "verification pass" introduced a fresh hallucination (`CustomsFiling.rawPayload`, `CustomsFiling.transactionTypeId`) while fixing others.

**Before landing any migration below, or before citing a field as COVERED/PARTIAL in future report revisions: grep the exact field name against `prisma/schema.prisma` and require a literal match.** A field that "should" exist on a model is not the same as a field that does.

## 1. Phase 1 — Entry Summary (7501) core gaps

Chapter 2, 160 missing / 33 partial fields — the highest single-chapter volume and the core filing type. Target: `prisma/schema.prisma`.

- **`CustomsFiling`** — add scalar 1:1 header fields that are missing outright: `brokerReferenceNumber`, `bondWaiverIndicator`, `bondWaiverReasonCode`, `liveEntryIndicator`, `consolidatedSummaryIndicator`, `paymentTypeCode`, `pgaDataIncludedIndicator`, `foreignTradeZoneIdentifier`, `usStateOfDestinationCode`, `estimatedEntryDate`, `dateOfImportation`, `designatedNotifyPartyNumber`, `grandTotalDutyAmount`/`grandTotalUserFeeAmount`/`grandTotalIrTaxAmount`/`grandTotalAdDutyAmount`/`grandTotalCvDutyAmount`/`grandTotalOtherRevenueAmount`.
- **New model `CensusWarningOverride`** — `filingId`, `sequence` (1-7), `conditionCode`, `overrideCode`. Closes the 14-field Census Warning Override gap (`CensusWarningOverrideInput`), one row per condition/override pair instead of 7 near-duplicate scalar slots.
- **New model `FilingFeeLine`** — `filingId`, `accountingClassCode`, `amount`, `sequence`. Replaces the single aggregate `feeAmount`/`dutyBreakdown Json` as the source of truth for itemized fees (499 HMF, 501 MPF, 311 Cotton, etc.). Closes `FeeTotalEntry`, `FeeTotalInput`, `HeaderFeesInput`, `LineUserFeeInput`, `IrTaxInput`, `OtherRevenueInput` (~20 fields).
- **New model `FtzDetail`** — `filingId` or `shipmentLineItemId`, `ftzAdmissionNumber`, `zoneId`, `privilegedStatusDate`, `merchandiseStatusCode`, `lineItemQuantity`, `currentHtsNumber`. Closes ~10 FTZ fields (`FtzStatusInput`, `FtzPrivilegedStatusDetailInput`, `TariffDetailInput.ftzPrivilegedStatusDetail`). Reused in Phase 2 for Cargo Release.
- **New model `AdcvdLineDetail`** — `shipmentLineItemId`, `adcvdOrderId` (FK to the existing `AdcvdOrder` reference table), `caseDepositRate`, `rateTypeQualifierCode`, `bondCashClaimCode`, `valueOfGoodsAmount`, `nonReimbursementDeclarationIdentifier`. `AdcvdOrder` stays as case-level reference data; this closes the filing/line-level gap the report's PARTIAL rows correctly flagged.
- **`InvoiceLine`** — add `lineRange1Begin/End` through `lineRange4Begin/End` and `supplierIdCode`. Closes `InvoiceLineReferenceInput` (10 fields) without a new model, since it's an extension of an existing 1:1 relation.
- **Line-level party/address** (`LineEntityGroupInput`, `LineEntityStreetAddressInput`, `LineEntityGeographicAreaInput`, `ArticlePartyInput`) — extend `ShipmentParty` with a `partyTypeCode` (M/C/S/E enum) and rely on `PartyAddress`/`PartyIdentifier` (already real models) rather than inventing new address storage.
- **Defer to Phase 3**: `StandardVisaInput`, `ImportersAdditionalDeclarationInput` (softwood lumber / 76-char declarations) — low volume, narrow use case.

## 3. Phase 1 — PGA Message Set

Chapter 8, 129 missing / 39 partial fields — the largest single-chapter field count. `PgaRequirement` already exists as a per-line-item flag; the gap is granular per-agency data (FDA, EPA, USDA, FWS, NOAA, etc.) spanning LPCO numbers, prior-notice confirmation numbers, vehicle/engine classification, temperature/lot/expiration tracking, can dimensions, harvest vessel details, species names, travel documents, inspection location.

Given the breadth spans 10+ distinct agencies each with a handful of fields, a hybrid is more proportionate than 100+ discrete columns:

- Add the **highest-frequency, cross-agency scalars directly to `PgaRequirement`**: LPCO number, LPCO type code, issuer code, permit type code (PG13/PG14), AOC code, FIRMS code / inspection location.
- Add a single **scoped `agencyData Json?`** field on `PgaRequirement` for the long tail of narrow per-agency fields (FDA prior-notice confirmation number, EPA vehicle/engine class, FWS genus/species + common name, NOAA harvest vessel name/flag/gear code/area, temperature/lot/expiration, can dimensions, travel document/crew passport). This is the one place a JSON catch-all is justified in this plan — it is bounded to one line item's PGA declaration, not a filing-wide catch-all (contrast with the `CustomsFiling.payload` fabrication corrected in the report). Document its shape by agency in a small companion type file so it doesn't become another opaque blob.

## 4. Phase 2 — Cargo Release, eBond, In-Bond, Broker Download

- **Cargo Release (chapter 4, 49 missing)**: extend `CustomsFiling` with `actionCode`, `importerOfRecordType`, `modeOfTransportationCode`, `estimatedEntryValue`, `splitShipmentReleaseCode`; add new model **`CargoReleaseBillOfLading`** (`filingId`, `billTypeIndicator`, `issuerCode`, `billOfLadingNumber`, `quantity`, `nonAmsIndicator`); reuse `FtzDetail` from Phase 1.
- **eBond (chapter 6, 21 missing)**: new model **`BondParty`** — `bondId`, `role` (enum: `PRINCIPAL` | `CO_PRINCIPAL` | `SURETY` | `CO_SURETY` | `REINSURER`), `idNumberType`, `idNumber`, `name`, `liabilityAmount`, `agentIdNumber`. One polymorphic-by-role model closes principal/co-principal/surety/co-surety/reinsurer gaps instead of 5 near-duplicate models (`PrincipalInput`, `CoPrincipalInput`, `SuretyInput`, `CoSuretyInput`, `ReinsurerInput`).
- **In-Bond 7512 (chapter 11, 44 missing)**: this is genuinely new domain data (in-transit bonded movement), not force-fittable onto `Shipment`. New model **`InBondRecord`** (`inBondNumber`, `inBondEntryType`, `carrierCode`, `bondedCarrierId`, `usPortOfDest`, `portOfForeignDest`, `value`, `ftzWarehouseInd`, plus BOL fields `masterBOLNumber`/`houseBillNumber`/`subHouseBillNumber` with issuer codes) and **`InBondEvent`** (`inBondRecordId`, `eventDate`, `eventTime`, `portOfArrival`, `carrierCode`, `cityName`, `stateCode`, `exportMOT`, `exportConveyance`).
- **ACE Broker Download (chapter 9, 78 missing)**: this chapter is CBP → filer inbound manifest/status data (read-only ingestion, not filer-authored), so it doesn't belong on `Shipment`/`CustomsFiling`. New lightweight model **`ManifestRecord`** (header: `transportationIndicator`, `countryCode`, `conveyanceName`, `manifestSequenceNumber`; per-bill: `billOfLading`, `foreignPortOfLading`, `manifestQuantity`/`Units`, `weight`/`weightUnit`, `houseBillNumber`, container details `equipmentNumber`/`sealNumbers`/dimensions). Lower priority than Phases 1 unless a live customer need is driving it now — confirm before building.

## 5. Phase 3 — Statement, query chapters, narrow edge cases

- **Statement (chapter 5, 44 missing / 31 partial)**: CATAIR daily/periodic statement records don't correspond to any existing model — they're their own periodic-reporting entity, not a `CustomsFiling` extension. New model **`StatementRecord`** (`accountId`, `statementType` enum Q1-Q6/periodic, `statementNumber`, `districtPort`, `filerCode`, `importerNumber`, `printDate`, `dueDate`, `entryType`, plus the indicator/flag fields currently MISSING) and **`StatementFeeLine`** (`statementId`, `accountingClassCode`, `amount`, `sequence` 1-5) for the itemized fee slots. The existing 31 PARTIAL rows (duty/tax/AD/CVD totals, correctly mapped to `CustomsFiling.totalDuties`/`totalTaxes` per the corrected report) should migrate to reference `StatementRecord` once it exists, rather than staying as filing-level aggregates.
- **Entry Summary Query (chapter 3, 21 missing) / Cargo Manifest Query (chapter 10, 13 missing)**: nearly all of these are transient query-request parameters — multi-slot entry-number/filer-code search criteria, date ranges, status flags (`EntryNumberQueryRequestInput` slots 1-5, `CriteriaQueryRequestInput` flags). These don't need to be persisted as schema fields; they belong in the query API request/response handling in `src/lib/abi/entrySummaryQuery` and `src/lib/abi/cargoManifestQuery`. Verify the query handlers accept/return them correctly rather than adding Prisma columns.
- **Low-volume deferrals**: standard textile visa numbers, softwood lumber 76-char declarations, biological/harvest-vessel detail beyond what Phase 1's PGA `agencyData` already covers — add on demand.

## 6. Cross-cutting items to resolve before or alongside this work

- **`CustomsFiling.entryType` is `@deprecated`** ("Use transactionTypeId instead") but `transactionTypeId` was never actually added — only the new `country`/`procedureCode`/`messageName` multi-country fields exist. Resolve this migration (finish it, or drop the stale deprecation comment if `entryType` is staying) before Phase 1 work builds more fields alongside a column mid-deprecation.
- **No JSON catch-all exists on `CustomsFiling`** today — `dutyBreakdown` is fee-scoped only. This is *why* the original report's PARTIAL claims via a fabricated `payload` field were wrong. Any future generic-JSON escape hatch must be an explicit, named, scoped field (like `PgaRequirement.agencyData` above), never an implied or assumed one.
- **Re-run the coverage report after each phase lands**, re-verifying every citation against `prisma/schema.prisma` literally (see §0), so the tracked MISSING/PARTIAL/COVERED counts stay honest as gaps close.
